Word book

The factory's words, in plain language. Each links to the room that explains it.

adapter
The plug between the controller and one agent runtime. It starts one run and settles with an outcome: completed with a claim, failed with a reason, or cancelled. It knows nothing about cycles or stages. src/adapter.ts. controller and owner
apply
The one pure function that decides what an event does to a cycle: apply(cycle, event, workflow) returns the next cycle. Every stage change in the factory goes through it. src/lifecycle.ts. workflows
base
The commit a cycle starts from, resolved to a full SHA before the cycle opens. The candidate must descend from it; if the target branch moves on, the cycle escalates. developer
budget
How many outcomes a stage may record in one cycle, set per stage by the workflow. The default: two standard reviews and one adversarial. A FAIL at the limit escalates; spent budget never resets inside a cycle. workflows
bwrap (bubblewrap)
A small Linux tool that runs a command in its own namespaces with only the directories you bind visible. The factory's default sandbox backend. sandbox and secrets
candidate
The commit under test: its head SHA and its base SHA. Set when the controller accepts a developer's claim; replaced only by a fix run. developer
check
A command the job declares, such as npm test, run by a command stage with no run of its own. The controller runs it on the candidate, not the developer. Exit 0 is PASS, anything else FAIL, a command that cannot start MISSING. command stages
checkout (verify)
A fresh copy of the candidate's files with no .git, made by the controller for a command stage and then read by the reviewers. command stages
child cycle
A new cycle for the same work, opened by the owner after an escalation. It names its parent and starts with every budget empty. The parent stays ESCALATED. workflows
claim
What an agent says it did, as JSON at the end of its reply: a developer's {head, artifacts}, a reviewer's {head, verdict, findings}. A claim is checked before it counts. controller and owner
command stage
A workflow stage where the controller runs commands on a fresh checkout of the candidate: the job's checks, or the stage's own run. How a step of your own joins a workflow. command stages
controller
The deterministic program that runs the factory: it opens cycles, starts runs, runs checks and records events. It is not an AI, and it is the only thing that changes state. controller and owner
cycle
One attempt to deliver one piece of work under one workflow: from QUEUED to ACCEPTED, ESCALATED or CANCELLED, with its own event log and budgets. workflows
deadline
How long a stage may take (deadlineMs in the job file). At the deadline the controller stops waiting, kills the run and records run_failed: timeout. controller and owner
dispute
A fix run's answer that keeps the previous commit and says why the findings are wrong. The cycle escalates with the reason; only the owner can weigh it. developer
escalation
The cycle stops in ESCALATED with a reason and waits for the owner, who moves it on in place (retry, overrule or route, each with a reason), opens a child cycle or cancels. Nothing retries by itself. workflows
event
One fact appended to a cycle's log: a claim, a result, a verification, a verdict, an owner decision. The cycle's state is what you get by applying them in order. event log
evidence
Each command's stdout, stderr and exit, written under evidence/<SHA>/<stage>/, with the request, the diff and what the command wrote in output/. Reviewers read it. Missing evidence is never a PASS. command stages
fix run
When a FAIL sends the cycle back to a commit stage, the developer runs again on the same branch, given the findings. It must make a new commit, or dispute. developer
grant
A credential the owner hands to one command stage: a name, the variable it is set in, and the file it is read from. A workflow asks for it; only your personal or job file gives it. Its value reaches that stage's commands and nowhere else. sandbox and secrets
head
The SHA of the commit at the tip of the cycle's branch: the candidate under test. developer
job file
A small JSON file the owner writes: work ID, ticket, repository, and anything to set for this job only. The last of the four configuration layers. configuration
kit
A test helper for one kind of extension (runtimeKit, commandKit, observerKit): you call it from your own test file, and it drives your extension the way the controller would. runtimes and kits
layer (configuration)
One of the four places a job's settings come from: factory defaults, your personal file, the repository at the base SHA, the job file. A later layer replaces an earlier one. configuration
nonce
A random string generated per review and put in every section header of the reviewer's prompt. A file in the commit cannot fake a header it has never seen. reviews
observer
Any process that reads the event stream and acts, only through accept and cancel, which record its name as the source. event log
owner
You: the human who writes tickets and configuration, accepts the exact SHA, merges, and decides every escalation. controller and owner
reject_dispatch
The event the loop records when a stage throws something it cannot classify. It escalates the cycle with the message and counts nothing. sim
replay
Rebuilding a cycle by feeding its stored events through apply from the start. The store never saves state, only events. event log
role text
An agent stage's one line of instructions, the first line of its prompt. Its hash, and the hash of the contract below it, are recorded on every outcome event. developer
run
One launch of one agent in one role, with its own run ID. A run has at most one outcome. controller and owner
run_failed
The event for a run that ended with no usable claim: crash, timeout, malformed reply, or a claim the controller refused. It escalates the cycle and is not a review attempt. controller and owner
runtime
The program that hosts an agent, chosen by name: claude, pi, or an extension module. Runtime, model and role are independent choices. runtimes and kits
sandbox
Where candidate code and agents run: only the directories their job needs, private /tmp, a cleared environment, and no network for commands unless a stage asks. src/sandbox.ts. sandbox and secrets
scope (systemd)
A transient systemd unit, sf-<runId>, that holds a run and everything it starts, so cancelling kills the whole tree. runtimes and kits
SHA
The 40-character hex name of a Git commit. The factory always uses the full SHA: a short one could name a different commit later. developer
stream (events)
The event log read in store-wide order, one JSON line per row with the stage it moved the cycle to: node src/main.ts events. event log
ticket
The contract for one piece of work: goal, done-when checks, constraints and non-goals. The developer and every reviewer read the same text. how this repo is built
verdict
A reviewer's answer: PASS or FAIL, the SHA it reviewed, and findings that name a file and line. reviews
work item
A stable work ID (workId in the job file). It has at most one open cycle at a time. event log
workflow
The stages a cycle goes through, as data: each stage's kind (agent, command or human), its PASS and FAIL transitions and its budget. Checked by checkWorkflow before anything runs and recorded by its hash when a cycle opens. The v1 lifecycle is defaultWorkflow. workflows
worktree (clone)
The developer's private clone on branch sf/<cycle>, the only place its sandbox may write. developer
