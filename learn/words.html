Word book

The factory's words, in plain language. Each links to the room that explains it.

adapter
The plug between the controller and one agent runtime. It starts one run and settles with an outcome: completed with a claim, failed with a reason, or cancelled. It knows nothing about cycles or stages. src/adapter.ts. controller
apply
The one pure function that decides what an event does to a cycle: apply(cycle, event) returns the next cycle. Every stage change in the factory goes through it. src/lifecycle.ts. lifecycle
base
The commit a cycle starts from, resolved to a full SHA before the cycle opens. The candidate must descend from it; if the target branch moves on, the cycle escalates. developer
budget
Per cycle: two standard reviews and one adversarial review. Counters only go up. A FAIL at the limit stops the cycle; spent budget never resets inside a cycle. review
bwrap (bubblewrap)
A small Linux tool that runs a command in its own namespaces with only the directories you bind visible. The factory's default sandbox backend. sandbox
candidate
The commit under test: its head SHA and its base SHA. Set when the controller accepts a developer's claim; replaced only by a fix run. lifecycle
check
A command the repository declares in the job file, such as npm test. The controller runs it on the candidate, not the developer. Exit 0 is PASS, anything else FAIL, a command that cannot start MISSING. verify
checkout (verify)
A fresh copy of the candidate's files with no .git, made by the controller for the checks and then read by the reviewers. verify
child cycle
A new cycle for the same work, opened by the owner after an escalation. It names its parent and starts with fresh counters (0, 0). The parent stays ESCALATED. lifecycle
claim
What an agent says it did, as JSON at the end of its reply: a developer's {head, artifacts}, a reviewer's {head, verdict, findings}. A claim is checked before it counts. controller
controller
The deterministic program that runs the factory: it opens cycles, starts runs, runs checks and records events. It is not an AI, and it is the only thing that changes state. controller
cycle
One attempt to deliver one piece of work: from QUEUED to ACCEPTED, ESCALATED or CANCELLED, with its own event log and review counters. lifecycle
deadline
How long a stage may take (deadlineMs in the job file). At the deadline the controller stops waiting, kills the run and records run_failed: timeout. controller
escalation
The cycle stops in ESCALATED with a reason and waits for the owner, who opens a child cycle or cancels. Nothing retries by itself. lifecycle
event
One fact appended to a cycle's log: a claim, a result, a verification, a verdict, an owner decision. The cycle's state is what you get by applying them in order. store
evidence
Each check's stdout, stderr and exit code, written under evidence/<SHA>/. Reviewers read it. Missing evidence is never a PASS. verify
fix run
After the first standard FAIL, the developer runs once more on the same branch, given the findings. It must produce a new commit with a new tree. developer
head
The SHA of the commit at the tip of the cycle's branch: the candidate under test. developer
job file
A small JSON file the owner writes: work ID, ticket, repository, checks, which runtime plays each role, sandbox and deadline. start
nonce
A random string generated per review and put in every section header of the reviewer's prompt. A file in the commit cannot fake a header it has never seen. review
owner
You: the human who writes tickets, accepts the exact SHA, merges, and decides every escalation. workflow
reject_dispatch
The event the loop records when a stage throws something it cannot classify. It escalates the cycle with the message and counts nothing. sim
replay
Rebuilding a cycle by feeding its stored events through apply from the start. The store never saves state, only events. store
run
One launch of one agent in one role (developer, standard reviewer, adversarial reviewer), with its own run ID. A run has at most one outcome. controller
run_failed
The event for a run that ended with no usable claim: crash, timeout, malformed reply, or a claim the controller refused. It escalates the cycle and is not a review attempt. controller
runtime
The CLI that hosts an agent: claude or pi. Runtime, model and role are independent choices. runtimes
sandbox
Where candidate code and agents run: only the directories their job needs, private /tmp, a cleared environment, and no network for checks. src/sandbox.ts. sandbox
scope (systemd)
A transient systemd unit, sf-<runId>, that holds a run and everything it starts, so cancelling kills the whole tree. runtimes
SHA
The 40-character hex name of a Git commit. The factory always uses the full SHA: a short one could name a different commit later. developer
ticket
The contract for one piece of work: goal, done-when checks, constraints and non-goals. The developer and both reviewers read the same text. workflow
verdict
A reviewer's answer: PASS or FAIL, the SHA it reviewed, and findings that name a file and line. review
work item
A stable work ID (workId in the job file). It has at most one open cycle at a time. store
worktree (clone)
The developer's private clone on branch sf/<cycle>, the only place its sandbox may write. developer
