Why a factory?

Coding agents can write a change in a minute. The hard part is knowing the change is right, without reading every line of every attempt yourself.

The factory puts your attention where it counts. Up front, you write a clear ticket. At the end, you look at a change that has already passed the checks and two kinds of review, and you decide.

Everything in between is run by a controller: a plain program, not another AI. It moves the work along, runs the checks itself, and stops to ask you whenever something does not add up.

The first goal

One READY ticket reaches a pull request you can review, with no one pushing it from stage to stage, and with a safe way to fail.

Five rules it never breaks

1 · The controller decides; agents claim

An agent saying "done, here is commit abc123" is a claim. The controller checks the commit exists, sits at the branch tip and changes something before anything moves.

2 · Evidence binds to one SHA

Check output and review verdicts name the exact commit they are about. A new commit makes the old evidence worthless. A verdict for the wrong SHA is counted but cannot move the cycle.

3 · A fixed review budget

Two standard reviews and one adversarial review per cycle. A FAIL at the limit stops. No endless "try again until it passes".

4 · Unclear means stop and ask

A crash, a timeout, a reply with no claim, a check that cannot run: the controller does not guess or retry. The cycle is escalated to the owner.

5 · Humans accept

The factory stops at AWAITING_ACCEPTANCE. You accept the exact SHA and you merge. Nothing merges or deploys itself.

And: agents are untrusted

The ticket, the code and every agent's output are treated as input from a stranger. Developer runs, checks and reviewers all run in a sandbox.
