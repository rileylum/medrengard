Layers

The rules

lifecycle.ts is the engine: pure functions over plain values, and the workflow as data. No disk, no clock, no processes. The scenarios in tests/scenarios.ts test it.

The memory and the hands

store.ts keeps the events and stream.ts reads them back. controller.ts starts runs and records outcomes. developer.ts, verify.ts and review.ts each serve one kind of stage, with the wording from prompt.ts. run.ts calls them by the stage's kind.

The outside world

runtime/ launches runtimes by name. sandbox.ts wraps every untrusted command. git.ts runs the controller's own Git. config.ts reads the four layers. main.ts is your command line.

Dependencies point one way: towards the rules. The engine imports nothing. kits/ sit beside the rest: each is a test helper for one kind of extension. The factory runs none of them; verify.ts takes only a type from one.
