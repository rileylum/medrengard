Three layers

The rules

lifecycle.ts is a pure function over plain values. No disk, no clock, no processes. Every rule of the spec lives here, and the scenarios in tests/scenarios.ts test it.

The memory and the hands

store.ts keeps the events. controller.ts starts runs and records outcomes. developer.ts, verify.ts and review.ts each own one stage. run.ts calls them in turn.

The outside world

runtime/ launches claude and pi. sandbox.ts wraps every untrusted command. git.ts runs the controller's own Git. main.ts is the owner's command line.

Dependencies point one way: towards the rules. The state machine imports nothing; the stage modules never import each other's internals; only main.ts knows the real runtimes by name.

Three seams

A seam is a place where you can swap what is behind it without changing what is in front. The design turns on three.

Adapter

Between the controller and a runtime. start(request, signal) settles with an outcome. Tests use a fake adapter; production uses cliAdapter for claude and pi. A new runtime is a new CliSpec.

controller

EventStore

Between the rules and the disk. append validates the serialised event, writes one row and returns the replayed cycle. Nothing else writes state.

event log

Sandbox

Between a command and the machine. A stage builds a Policy; wrap turns the command into one that runs inside the chosen backend (bwrap or none). Docker or a VM would be another case of wrap.
