Agents claim. The controller decides.

The controller is ordinary code, not a language model. It starts each run, waits for it, and writes down what happened.

An agent can say anything: "I committed abc123", "the tests pass", "PASS". Each of those is a claim. The controller checks what it can, and only then turns the claim into an event. What the event means is the engine's to decide.

What the controller does for every run

  1. Mints a run ID. For a role that commits, records a claim event first.
  2. Starts the adapter with a deadline.
  3. Takes whatever comes back, and makes it plain data.
  4. Writes exactly one event: a result, a dispute, a verdict, or run_failed.

"Exactly one" holds even when the adapter crashes, hangs, lies or returns rubbish.

The adapter seam

An adapter has one job: start one run and settle with an outcome. It knows nothing about cycles, stages or events.

There are three outcomes: completed with a claim, failed with a reason, or cancelled. The claim is unchecked JSON. The controller classifies it, by the role alone: a role whose stage commits gives a result or a dispute, any other a verdict.

That is why the factory can swap claude for pi, an extension, or a test double, without touching the engine. Runtimes and kits


  






  
Every run has a deadline

  
A runtime can simply never answer. The 03-a spike saw claude -p fail to return for a one-turn prompt in four runs of ten. So execute refuses to start a run without a deadline.

  
bounded races the adapter against a timer. When the timer wins, the outcome is failed: timeout, and only then is the adapter told to abort. Whatever the adapter does afterwards lands on a promise that has already settled, and is dropped. So even an adapter that ignores the abort cannot hold a cycle.

  
A settled cycle ends the race early, the same way. Once a second, execute reloads the cycle: if another process has settled it (the owner ran cancel), the outcome is cancelled and the adapter kills its CLI.

  
Why not just await the adapter? Because a throw inside start(), a rejection, a late answer and no answer must all become one well-formed event. bounded turns all four into an outcome.
