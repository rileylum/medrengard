From a ticket to a pull request

Pick a scenario and press ▶. The real controller takes the ticket through every stage. In autopilot a script plays the agents at the speed you pick. In Step through the same script waits for you to press Next before each action. Switch to I play the agents and you choose what the developer commits, how each check behaves and what each reviewer says.

Amber is the controller: it decides. Cyan is an agent: it only claims. Violet is you, the owner: you accept, cancel or start again. Click any stage in the diagram to see where it can go next. Click a row in the event log to see its JSON.

Things to try

Break the claim

In I play the agents, commit, then edit the reply: delete the json block, put in a short SHA, or name the base commit. The controller never takes the agent's word for it.

Spend the budget

FAIL the first standard review. A fix run starts. FAIL it again: the cycle stops and waits for you. Open a child cycle and the counters start again at (0, 0).

Interfere

While a run is going, press Owner cancels or main moves on. The agent finishes, and its result changes nothing: the store has already settled the cycle.

Make a check go missing

Open the job file and add {"name": "lint", "command": ["eslint", "."]}. This made-up machine has no eslint, so the check is MISSING, and missing is never a PASS.

Let it time out

Set the deadline to 5 s and press Go silent as the developer. The controller stops waiting at the deadline and records run_failed: timeout.

Ship two tickets

Accept, merge, then press Next ticket. The next cycle's base is the merge commit: every run starts from the repository's current tip.

What is real here, and what is pretend

The loop never decides

run() calls develop() once, then looks at the cycle's stage and calls the module for it. It never moves a stage itself: each module records an event, and apply decides where that leaves the cycle. When the stage is one no module acts on (AWAITING_ACCEPTANCE, ESCALATED, CANCELLED), the loop returns.

If a stage throws, the loop cannot tell what happened, so it does not guess. It records reject_dispatch with the message, which escalates the cycle, and the owner decides.
